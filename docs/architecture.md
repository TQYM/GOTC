# 技术架构

## 总体结构

```
┌────────────────────────────────────────────┐
│  frontend/  Next.js + React + Canvas        │
│  · 地块渲染层（程序化生成，无美术资源）        │
│  · 拖拽规划层（React DnD）                   │
│  · 三栏信息流（市民微博 / 新闻 / 导师点评）    │
│  · 终局雷达图 + 10 年推演动画                │
├────────────────────────────────────────────┤
│  backend/  FastAPI（轻量编排层）              │
│  · 模拟引擎：格子自动机 + 简化交通流           │
│    （自研纯 Python，500 格 × 20 分钟无压力）  │
│  · AI 编排：并行调多模型，SSE 流式推送         │
│  · 地块生成器：Perlin noise + 道路网络算法    │
└────────────────────────────────────────────┘
```

前端与后端之间：**REST（地块/状态）+ SSE（AI 反馈流）**。

## AI 模型分工

| 角色 | 模型 | 职责 |
|---|---|---|
| 前端开发主力 | Claude Opus | 全部前端代码：Canvas 渲染、拖拽交互、流式 UI |

> 国产模型跑满一天 API 成本不足一杯咖啡，放开调用频率本身就是玩法的一部分。

## 关键决策

- **程序化生成 > 真实 OSM 数据**：48 小时工期下零依赖、零清洗、零版权风险，且保证每局地块不同。
- **模拟引擎轻量自研**：不引入游戏引擎，500×500 格子的格子自动机 + 简化 BPR 交通流，Python 足够。
- **三流并行 SSE**：三条 AI 反馈流独立推送，前端分别渲染，互不阻塞。
