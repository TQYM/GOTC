# 00 · 总体规划

## 项目定义

**CITY20**：AI 驱动的城市规划模拟沙盘。单局硬上限 20 分钟：玩家在程序化生成的地块上完成城区规划，确定性模拟引擎实时推演城市运行，AI 三角色（数据大脑 / 市民之声 / 规划导师）以自然语言反馈每个决策；终局生成五维诊断报告与可分享 city card。

## 范围边界

**做（IN）**
- 程序化地块生成（地形 / 河流 / 既有道路）
- 6 大类 14 种可放置区块（见 [01](01-domain.md)）
- 确定性模拟引擎：人口、地价、交通（BPR）、污染、财政、幸福度
- AI 叙述层：三种角色的流式文本反馈
- 20 分钟游戏状态机（建设期 → 微调期 → 终局推演）
- 五维评分 + 雷达图 + 诊断报告 + city card 分享图
- 隐藏结局判定
- 四端交付（macOS / Windows / Android / iOS）：Web 代码复用 + Tauri / Capacitor 壳（见 [09](09-cross-platform.md)，里程碑 M6）

**不做（OUT）**
- 用户账号 / 持久化数据库（单局制，会话存内存）
- 多人协作 / 对战
- 真实地理数据（OSM）
- 原生界面重写（四端一律 Web 壳复用，见 [09](09-cross-platform.md)）
- 音效音乐（PR-17 为可选增强，赛事时间不够直接砍）

## 核心设计哲学

1. **模拟与叙述分层。** 数值世界（sim 引擎）是骨架，AI 世界（叙述层）是血肉。骨架必须脱离血肉独立成立——AI 供应商挂了、超时了、乱说了，游戏数值依然正确、流程依然完整。AI 输出永远携带 `source: "ai"` 标记，前端对 AI 文本做降级展示（占位文案库）。
2. **每个格子都有规划学意义。** 所有数值参数对标真实规范（GB50180-2018 生活圈体系、BPR 交通模型），规划导师的点评引用真实理论条目（理论库见 [04](04-ai-roles.md) 附录）。
3. **20 分钟是设计出来的，不是砍出来的。** 三个节奏阀门：建设期 15 分钟（足够 40–70 次放置决策）、微调期 2 分钟倒计时（制造最后取舍）、终局推演 10 年快进（给情绪一个落点）。

## 全局架构

```
浏览器 (Next.js)
  ├── Canvas 沙盘 ────────────┐
  ├── 拖拽面板 / 指标条         │  REST: 放置/拆除/查询
  ├── 三栏信息流 (SSE) ────────┤  SSE:   事件流
  └── 终局报告                │
                              ▼
                    FastAPI 编排层
                      ├── Session 管理（内存）
                      ├── Sim 引擎（纯函数，确定性）
                      ├── 事件总线（放置→指标diff→触发器）
                      └── AI 编排层（OpenAI 兼容，可插拔 provider）
```

**数据流向**（单向）：
`玩家操作 → REST → Session 状态变更 → Sim 重算 → 指标 diff → 事件总线 → ① SSE tick 推前端 ② 触发器判断 → AI 调用（异步）→ SSE news/citizen/mentor 推前端`

## 风险登记册

| 风险 | 概率 | 预案 |
|---|---|---|
| LLM 流式延迟拖垮节奏感 | 中 | AI 输出全部异步 + 前端打字机效果兜底；tick 事件不依赖 AI（M3 验收标准已强制） |
| 数值平衡崩了（分数全 0 或全 100） | 高 | PR-18 预留 3h 专职调参；参数全部集中在 `backend/app/sim/config.py` 一个文件 |
| Canvas 拖拽手感差 | 中 | PR-05 验收含"10 次连续放置无一次误触"的人工测试；手感问题不拖到 D2 |
| SSE 在代理/防火墙下断流 | 低 | 前端 EventSource 自动重连 + 后端支持 Last-Event-ID 续传（PR-13） |
| 时间不够 | 中 | 砍单顺序：M6 四端（按 [09 §8](09-cross-platform.md) 优先级，先 iOS 后桌面保 Android）→ PR-17 打磨 → 隐藏结局 → 环境事件池 → 导师理论引用 |
