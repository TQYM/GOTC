# 11 · 真实北京 + 3D 渲染（地形与渲染层重大变更）

> 需求（m00458/m00465）：3D 渲染，建模采用**真实北京**——不是北京风格，是真实地理数据。本文档取代 01 §1（随机地形为主模式）、05 §1/§4（Canvas 2D 渲染）的对应内容；数值模拟引擎（03）全部保留。原随机生成降级为「自定义沙盒模式」保留。

## 1. 决策摘要

| 项 | 原方案 | 新方案 |
|---|---|---|
| 地块来源 | seed 随机生成 48×48 | **真实北京片区 GIS 数据栅格化**到同一网格体系 |
| 玩法语义 | 平地造新城 | **真实片区的城市更新**（玩家角色=城市管理者，与 10 号文档一致） |
| 渲染 | Canvas 2D 伪 2.5D 等距 | **Three.js + React Three Fiber 真 3D**（既有建筑 + 玩家新区块同场景） |
| 既有建筑 | 无 | OSM 真实建筑轮廓拉伸为 3D 底座，是「不可随意抹去」的现状 |
| 现场联网 | 不需要 | 仍然不需要：**数据全部离线预处理、打包进仓库** |

为什么玩法改为城市更新而不是平地造城：真实北京片区几乎没有空地，空地造城反而失真；「存量更新」恰是真实北京规划政策主线（疏解整治促提升），叙事更硬，数值引擎（人口/通勤/污染/财政）无需任何改动。

## 2. 片区选择与网格

| 片区 | 范围 | 网格 | 特色 | 建议 |
|---|---|---|---|---|
| **朝阳 CBD–通惠河**（默认） | 约 2.4×2.4km：西起东大桥、东至四惠、北抵朝阳路、南临通惠河 | 48×48 @50m | 超高层集群 + 河道 + 居住混合，通勤/地价戏剧性强 | 首发 |
| 回龙观 | 约 3.2×3.2km | 64×64 @50m | 睡城通勤难题，治理叙事强 | 备选第二图 |
| 中关村西区 | 约 2.4×2.4km | 48×48 @50m | 高校/科技园混合 | 备选 |

- 网格规则不变（坐标 `r,c`、anchor、占地形状），只是地形从「生成」变「加载」。
- 多片区 = 开局选择界面加一栏；每片区一个数据包目录。首发只做 1 个，第二个片区是砍单首选。
- 网格分辨率不做 25m（建筑细节由矢量层负责，网格只服务数值；提高分辨率会让 sim 重算成本翻倍且对玩法无收益）。

## 3. 数据源与许可（已联网核实，2026-11）

| 数据 | 来源 | 获取方式 | 许可 | 用途 |
|---|---|---|---|---|
| 路网/水系/绿地/土地利用/建筑轮廓与层数 | **OpenStreetMap** | [BBBike 城市 extract](https://download.bbbike.org/osm/extract/)（支持 Beijing，pbf/shp 直出）或 Geofabrik 中国包裁剪；小范围可用 Overpass Turbo 导出 | **ODbL 1.0**：可商用，须署名「© OpenStreetMap contributors」，衍生数据库同许可共享 | 地形层 + 既有建筑层 + 道路网络 |
| 地形高程 | **Copernicus DEM GLO-30**（30m） | [Earth Data Hub](https://earthdatahub.destine.eu/collections/copernicus-dem/datasets/GLO-30) / AWS Open Data 镜像 | 免费，须注明「© DLR e.V. / © ESA」 | 3D 地形起伏（片区内高差小，可选） |
| 地铁线路与站点 | OSM `railway=subway` + `station` | 同上 | ODbL | trans_metro 放置约束与既有线路渲染 |
| 建筑高度补全 | OSM `height`/`building:levels` 缺失时按 §6 默认层高表 | — | — | 北京 OSM 高度标签覆盖不全（学界有专门用 SAR/街景补全的研究，见 [Zenodo 记录](https://zenodo.org/records/10443329)），**必须有默认层高兜底** |

**红线：比赛现场不请求 Overpass/任何在线瓦片服务**——公共 Overpass 有限速与内存溢出风险（大数据量查询常见失败），所有数据提前离线处理成静态文件。

## 4. 离线数据管线（tools/prepare-parcel/）

五步流水线，输入原始 extract，输出游戏数据包。**PR-27 归前端**：管线语言由前端自选（Python/Node 均可），只跑一次，产物入库。

| 步骤 | 动作 | 关键参数 |
|---|---|---|
| 1. 裁剪 | 按片区 bbox 裁剪 pbf | bbox 以经纬度写在 `parcels.yaml` 配置里 |
| 2. 投影 | 全部几何投影到 **EPSG:32650（UTM 50N）** | 北京中央经线 117°E，UTM 米制坐标直接对齐 50m 网格；禁止用 Web Mercator 直接量距（纬度畸变） |
| 3. 栅格化地形 | 矢量要素 → 48×48 格地形表 | 映射规则见 §5；多要素重叠时优先级：既有建筑 > 道路 > 水系 > 绿地 > 空地 |
| 4. 矢量层导出 | 建筑轮廓（含高度）、道路中心线、水系面 → 简化后 GeoJSON | Douglas-Peucker 简化容差 2m；建筑按格分片便于前端按需加载 |
| 5. 打包 | 输出到 `data/parcels/<parcel_id>/` | 见下方数据包结构 |

数据包结构（每片区一套）：

| 文件 | 内容 | 体积预算 |
|---|---|---|
| `parcel.json` | 元数据（名称、bbox、EPSG、网格尺寸）+ 48×48 地形表 + 可建造格掩码 + 初始既有设施清单 | <200KB |
| `buildings.json` | 既有建筑轮廓（投影后米制坐标）+ 高度/层数/类别，按 8×8 格分片 | <2MB |
| `network.json` | 道路/地铁中心线（3D 渲染与 sim 道路图共用） | <300KB |
| `terrain.bin`（可选） | DEM 高程网格 Float32 | <40KB |

**许可落点**：`data/parcels/*/LICENSE.txt` 每片区一份（OSM 署名 + 衍生数据 ODbL 共享声明）；前端「关于」弹层展示同样署名。

## 5. 栅格化映射与可建造规则

OSM 要素 → 地形/格类型映射（在 01 §1 六值基础上扩展）：

| OSM 要素 | 映射 | 可建造性 |
|---|---|---|
| `building=*` 覆盖格 | 新增地形值 `occupied`（既有建筑） | **不可放置**；拆除既有建筑是独立操作 `redevelop`（见下） |
| `highway=primary/secondary/...` | `road_inherited`（既有道路） | 不可放置；道路等级从 OSM 标签映射 sim 道路容量 |
| `waterway`/`natural=water` | `river` | 不可放置（桥除外） |
| 河岸缓冲 | `bank` | 仅公园/广场/步道类 |
| `landuse=forest`/`leisure=park` | `forest` | 可放置但触发林地抗议事件（03 已有） |
| `landuse=industrial` 现状 | `occupied`（既有厂房） | 可 redevelop（首钢式更新叙事） |
| 其余空地/低效用地 | `flat` | 自由建造 |

**redevelop（更新改造）**：对 `occupied` 格的新操作——支付现状建筑「拆迁成本」（按建筑面积×片区地价系数）后变为 `flat`，人口/岗位按现状估算瞬时扣除，幸福度短期 -5（搬迁阵痛），随后可自由放置。这是真实片区模式的核心决策张力：每一寸新建设都要付真实代价。`redevelop` 走与 place/remove 相同的契约形状（新操作类型，契约只增不改）。

**既有建筑产出**：`occupied` 格按建筑类别估算现状人口/岗位计入初始指标（住宅按层数×基底×人均面积，商业按建筑面积），保证开局指标是「一个真实运转的城区」而非零。

## 6. 3D 渲染规格（前端）

### 6.0 美术方向：卡通风格（m00594 决策）

整体定位「卡通城市沙盘」：真实北京的地理骨架 + 卡通化的视觉皮肤，参考 Townscaper / 纪念碑谷式的明快观感，而非写实渲染。
> ⚠️ **m00803 修正**：卡通 = 真实北京的**平滑曲线化**，不是大方块；识别度优先（一眼认出是什么）。轮廓平滑/屋顶/识别套件/真实地名标注的完整规格以 [13 §1/§2](13-refined-art-and-interaction.md) 为准，本节配色板继续有效。

- **着色**：MeshToonMaterial + 3 阶 gradientMap（toon shading），平行光主光 + 半球环境光；阴影用软 shadow map，不做 PBR 写实材质。
- **配色板**：全局高明度、中高饱和。地形——flat 米白 `#F5F0E6` / hill 浅赭 `#D9C7A7` / river 卡通蓝 `#7EC8E3` / bank 浅蓝 `#BFE3F2` / forest 青绿 `#8FD19E` / road 浅灰 `#C9CDD3`。
- **既有建筑**：pastel 灰白系（`#E8E6E1`～`#D5D2CC`），低饱和、弱存在感，衬托玩家决策。
- **玩家建筑**：按大类高饱和——住宅暖黄 `#FFC94D`、商业金橙 `#FF9F43`、工业雾紫 `#A29BFE`、绿地青绿 `#2ECC9B`、服务珊瑚红 `#FF6B6B`、交通天蓝 `#54A0FF`、市政灰蓝 `#8395A7`。
- **比例语言**：平滑、精致、可辨认——轮廓曲线平滑（非体素方块），屋顶按类型做坡顶/檐口线，树木用球状树冠；地标保持识别性轮廓与手工特征件（详见 [13 §1](13-refined-art-and-interaction.md)）。
- **描边**：可选（OutlinePass 或反向壳法），性能紧张时优先砍描边，不砍帧率。
- **动效**：落子 Q 弹（scale 回弹 200ms）、拆拆除尘（粒子小云朵）、推演镜头缓慢拉远——一律 ≤300ms，不抢决策时间。

### 6.1 技术栈

| 项 | 选型 | 理由 |
|---|---|---|
| 引擎 | Three.js + @react-three/fiber + @react-three/drei | React 生态与 Next.js 契合；drei 提供 OrbitControls/实例化工具 |
| 相机 | 透视相机 + OrbitControls（旋转/缩放/平移；触屏单指旋转、双指缩放平移） | 09 §5 触屏映射延续 |
| 坐标 | 与 EPSG:32650 对齐的米制局部坐标，片区中心为原点 | 避免大浮点误差 |
| 光照 | 1 方向光 + 半球环境光；阴影桌面开、移动关（假 AO 贴地色块代替） | 性能 |
| 拾取 | Raycaster 对地面网格平面求交 → 换算 r,c | 拖拽/点选放置的 3D 等价物 |

### 6.2 场景分层

| 层 | 内容 | 渲染方式 |
|---|---|---|
| 地形层 | 地面网格（按地形值顶点着色）+ DEM 起伏（可选） | 单 mesh + 顶点色；水面单独半透明材质 |
| 既有建筑层 | OSM 轮廓沿高度拉伸 | **按类别合并 BufferGeometry**（不按栋建 mesh）；灰色系低饱和，与玩家建筑区分 |
| 玩家建筑层 | 14 种区块的程序化模型（楼体+屋顶+类别色） | **InstancedMesh 按区块类型合批**；放置预览=半透明 ghost + 格框红绿 |
| 道路/地铁层 | network.json 中心线生成条带几何；地铁高架段加桥墩 | 合并几何 |
| 动效层 | 落子弹跳、推演镜头拉远、人口车流粒子（砍单项） | ≤300ms，延续 05 §4 |

### 6.3 既有建筑高度兜底（OSM 高度缺失时）

| building 标签 | 默认层数 | 默认层高 |
|---|---|---|
| `building=house`/`hut` | 1 | 3.5m |
| `building=apartments`/`residential` | 6 | 3m |
| `building=commercial`/`retail` | 3 | 4m |
| `building=office` | 12 | 3.5m |
| `building=industrial`/`warehouse` | 1 | 7m |
| 其余无标签 | 2 | 3.5m |

有 `building:levels` 用层数×层高；有 `height` 直接用。CBD 核心地标（中国尊/央视大楼/国贸三期）手工标注真实高度进数据包（个位数建筑，人工值得）。

### 6.4 性能预算与验收

- 既有建筑合并后 draw call ≤ 20；玩家建筑 instanced 后 ≤ 14；全场景 draw call ≤ 60。
- 桌面（M 系 Mac Chrome）1080p ≥55fps；Android 中端机 WebView ≥30fps；像素比移动端上限 1.5。
- 首屏数据包加载 ≤3s（本地服务）； buildings 分片按视野懒加载。
- 四端 WebGL2：macOS Safari/Chrome、Windows Chrome/Edge、Android System WebView、iOS WKWebView（15+）均支持，写进 09 §5 验收。

## 10. 验收（追加到 07 比赛日清单）

1. 默认片区与真实地图（打印一张 OSM 同范围截图）叠图对照：路网走向、水系、绿地位置一致。
2. 建局即见真实既有建筑 3D 场景；中国尊等地标可辨认。
3. redevelop 一处既有厂房 → 指标扣除 → 放置新住宅 → 全链路数值正确。
4. 全程断网可玩（数据包本地）；四端帧率达 §6.4。
5. 沙盒模式（随机 seed）仍可建局，证明旧模式未回归。
