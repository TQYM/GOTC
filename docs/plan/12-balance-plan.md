# 12 · 数值平衡执行方案

> 本文是 CITY20 的数值平衡工作单。它定义调参顺序、目标区间、策略样本和验收门槛；在完成样本局记录前，不直接把候选值写进生产配置。

## 1. 平衡目标

数值平衡服务于一局 20 分钟的决策密度，而不是追求所有策略得到相同分数。玩家应该能感受到清晰的取舍：住宅带来人口和税收，工业提供岗位但带来污染，地铁改善交通但挤压建设预算，绿地和公共服务提升幸福度但不直接产生岗位。

首轮调参的目标是：

| 目标 | 验收口径 |
|---|---|
| 新手可完成一局 | 只放住宅、商业、道路和 1 个公共服务时，不因维护费在第 3 年前破产 |
| 混合规划有优势 | 混合策略的五维总分处于 60–80，且不依赖单个稀有区块 |
| 专项策略有代价 | 全住宅、工业优先、绿地优先、地铁优先都能形成清晰强项，同时至少有两个明显短板 |
| 结局有区分度 | `ordinary` 是常见结果；`thriving` 需要完整规划；`bankrupt`、`gridlock`、`ghost_town`、`eco_paradise` 均可通过明确行为触发 |
| 分数不饱和 | 正常策略不应出现五维全 0 或全 100；单项 95 分以上必须对应明确的专项投入 |
| 预算有决策感 | 建设结束时仍保留现金，但不能同时无成本拥有高人口、高服务、低拥堵和高绿地 |

目标区间是校准用的参考带，不是对每个随机地块的硬断言。地形差异和 seed 变化应允许结果在区间上下浮动。

## 2. 当前基线的硬问题

平衡调参前先锁定这些规则语义，否则样本局之间不可比较。

| 优先级 | 问题 | 当前表现 | 处理决定 |
|---|---|---|---|
| P0 | 绿地率口径不一致 | `backend/app/sim/green.py` 将未被铲除的 forest 计入 `green_ratio`，而 `03-sim-engine.md` §4.6 仍描述为玩家放置绿地占建设区块比例；空森林地块可直接满足 `eco_paradise` | 在调参前二选一并同步 01/03/测试。推荐保留自然生态分数，但改名为“生态覆盖率”，另设“建设绿地率”供玩家规划评分使用；若不扩展契约，则按文档改回建设绿地率，并让生态结局显式检查自然林地占比 |
| P0 | 人口评分公式漂移 | 规划文档使用 20,000 人目标，代码使用 `住宅容量 × 0.95` 作为满分分母；一座 `res_mid` 就能拿到人口满分 | 增加 `score_target_population` 配置，先按固定目标评分；若试玩显示分数过低，再采用 `max(score_target_population, 住宅容量×0.95)` 的过渡口径，并记录理由 |
| P0 | 交通评分公式漂移 | 文档写 0.6 通勤 + 0.4 拥堵、拥堵上限 1.5；代码实际为 0.5 + 0.5、拥堵上限 2.0 | 选定一个版本后同步 01/03/代码。推荐先采用文档版本，让通勤规划比单点地铁更重要 |
| P1 | 税收与维护费量级失衡 | 单座 `res_mid` 约 855 人，人口税约 102.6 万/年，而住宅维护费仅 1.2 万/年；税收几乎不构成取舍 | 将 `TAX_PER_PERSON`、`TAX_PER_JOB` 和各类维护费移入平衡配置，做税收/维护费比率扫描 |
| P1 | 目标布局超出实战预算 | 测试中的 thriving 样例包含住宅、工业、地铁、学校、医院，目录造价约 792 万，超过当前 500 万初始资金；测试绕过了放置资金校验 | 在不改测试语义前，先定义“可达 thriving 样例”的预算上限；候选方案是提高初始资金，或降低地铁/医院组合成本，不能只在文案中宣称可达 |
| P1 | 参数散落在代码 | 税率、人口吸引力、幸福度权重、迁移上限、逃离潮和结局门槛分散在多个 Python 模块 | 增加 `balance` 配置段；代码常量只保留枚举和不可调的结构规则，所有可调数值由 YAML 加载 |

## 3. 参数分层与调参顺序

每轮只改一层参数，避免无法判断因果。任意单项改动超过 20% 时，必须附带五种策略的完整记录。

### 3.1 第一层：预算与现金流

先解决“能不能建立城市”，再调评分。

建议新增以下配置项，并保留当前值作为第一组对照：

```yaml
balance:
  score_target_population: 20000
  tax_per_person: 1200
  tax_per_job: 500
  migration_limit: 0.08
  exodus_threshold: 40
  exodus_penalty: 0.05
```

候选扫描范围：

| 参数 | 当前值 | 首轮候选范围 | 选择标准 |
|---|---:|---:|---|
| `initial_funds` | 5,000,000 | 5,000,000 / 6,000,000 / 7,000,000 | 混合策略可完成基础服务；地铁优先仍需放弃另一项投入 |
| `tax_per_person` | 1,200 | 300 / 450 / 600 | 单座 `res_mid` 年净现金不超过其造价的 25% |
| `tax_per_job` | 500 | 250 / 350 / 450 | 单个工业区块不能单独覆盖全城所有维护费 |
| 住宅维护费倍率 | 1.0 | 1.0 / 1.5 / 2.0 | 全住宅策略应有财政压力，但不应开局必破产 |
| 公共服务维护费倍率 | 1.0 | 0.8 / 1.0 / 1.2 | 学校和医院应成为持续成本，而不是一次性购买即无代价 |

首轮不同时改初始资金和税率：先固定 500 万扫描税率，再根据“混合/地铁优先”的可玩性决定是否增加预算。

### 3.2 第二层：空间与交通

交通应奖励连续路网和职住邻近，而不是让单座地铁站消除全部问题。

- 保留 BPR 形式和 `bpr_alpha=0.15`、`bpr_beta=4`，先不改公式。
- 对普通道路容量做 `800 / 1000 / 1200` 三档扫描；目标是一个中等住宅区配一条道路时 `congestion` 约 0.5–0.9，而非天然超过 1。
- 地铁固定通勤保留明显优势，但把“强效果”与“高机会成本”绑定：先扫描 `metro` 造价 2.5M / 3.0M / 3.5M，固定通勤 8 / 10 分钟，不同时降低造价和时间。
- 道路容量改变后，重新记录 `gridlock` 门槛；不得用提高结局门槛掩盖路网过载。

### 3.3 第三层：人口、幸福度与服务

人口和幸福度要对空间关系敏感，但不能因为缺一个设施就断崖式归零。

- 先保持住宅容量比例 `300 / 900 / 2400`，只调整吸引力权重；如高层占比过高，再处理 `res_high` 的拥挤惩罚。
- 目标是公共服务覆盖率达到 60% 左右时幸福度明显改善，达到双覆盖 90% 以上时获得高分但仍受通勤、污染和职住比约束。
- 绿地率 0.25–0.35 应能支撑健康城市；超过 0.55 才进入生态结局候选，不让少量公园直接触发隐藏结局。
- 逃离潮只惩罚连续低幸福度城市，不应成为普通工业布局的即时死亡开关；先固定两年触发，再只扫描额外迁出比例 3% / 5% / 8%。

## 4. 五种策略样本

每种策略使用相同的 5 个 seed 和同一套可建设格选择规则。建议固定 seed：`882314`、`20261107`、`13579`、`24680`、`424242`。每局记录建设结束、推演第 3 年和第 13 年三个时点。

| 策略 | 核心操作 | 预期强项 | 必须存在的短板 |
|---|---|---|---|
| 全住宅 | 住宅占建设区块 ≥70%，最多 1 个商业 | 人口、早期现金流 | 职住比、通勤、服务覆盖 |
| 工业优先 | 轻/重工业占就业区块 ≥50% | 岗位、税收、职住比 | 污染、幸福度、住宅吸引力 |
| 绿地狂魔 | 建设绿地率 ≥45%，无重工业 | 幸福度、生态覆盖 | 岗位、人口、财政 |
| 地铁狂魔 | 至少 2 个地铁站，交通投入 ≥总造价 35% | 通勤、拥堵 | 预算、服务或绿地投入不足 |
| 混合规划 | 住宅、就业、道路、绿地、学校/医院各有投入 | 综合分和结局稳定 | 不应在任何单项上碾压专项策略 |

策略不按固定“最优落点”写死，而是按占比和预算约束定义，避免测试只验证某一张地图。

## 5. 验收门槛

完成一轮候选参数扫描后，生成一张 CSV/Markdown 表，至少包含：`seed`、策略、总造价、建设结束资金、最终资金、人口、岗位、职住比、绿地率、通勤、拥堵、污染、幸福度、五维分数、结局。

候选配置只有同时满足以下条件才可进入生产：

1. 五种策略各跑 5 个 seed；混合规划平均总分 60–80，且没有一项连续 0 分。
2. 全住宅、工业优先、绿地狂魔、地铁狂魔各自至少有一个维度比混合规划高 10 分，同时至少有一个维度低 10 分。
3. 混合规划和至少一种专项策略在 5 个 seed 中均无预算校验失败；工业优先允许出现破产，但不能 5 局全破产。
4. `thriving` 需要同时满足幸福度、职住比和交通门槛；不能仅靠一座地铁或一片绿地触发。
5. `eco_paradise` 必须同时满足自然/建设绿地口径、人口和无工业条件；空地或全森林测试不得无条件获得该结局。
6. `gridlock`、`ghost_town`、`bankrupt` 各至少有一条可复现操作路径，且普通混合策略不应在 5 局中频繁误触发。
7. 评分分布不能饱和：正常样本五维平均分不高于 90，专项最高项允许达到 90 以上但不能五维同时达到 95。

## 6. 实施顺序

1. 先修正 §2 的 P0 规则口径，并同步 `01-domain.md`、`03-sim-engine.md`、实现和黄金样例。
2. 将可调常量集中到 `backend/sim-config.yaml` 的 `balance` 段；`economy` 保留阶段和资金，`balance` 负责税率、评分和迁移。
3. 增加一个只读的平衡报告脚本，输入 seed 和策略，输出上述字段；脚本不得改变游戏状态或随机数顺序。
4. 按“现金流 → 交通 → 幸福度/服务 → 结局”的顺序扫描，每轮只发布一个候选配置。
5. 将最终五局记录和选值理由补入 README，并把 PR-18 的 DoD 链接到本文。

生产配置确定后，必须同时更新：`backend/sim-config.yaml`、`docs/plan/01-domain.md`、`docs/plan/03-sim-engine.md`、相关测试黄金值和 README 平衡记录。没有样本局记录时，禁止只凭单局试玩修改参数。
