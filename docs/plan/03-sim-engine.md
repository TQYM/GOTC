# 03 · 模拟引擎（后端·数值核心）

> 游戏唯一的"物理定律"实现。本文档只写**计算规则与参数**，不写实现代码。所有公式以文字 + 参数表表达，参数集中放在 §8 配置表，调参只改配置不改逻辑。
> ⚠️ **变更**：§2 世界生成在默认模式被真实片区加载（parcel_loader）取代，见 [11](11-real-beijing-3d.md)；真实片区的初始人口/岗位含既有建筑产出（[11 §5](11-real-beijing-3d.md)）；本文全部数值公式不变。不限时改造见 [10](10-persistence-sync.md)。

## 1. 设计原则

1. **确定性**：相同 seed + 相同操作序列 ⇒ 相同终局。所有随机（事件文案挑选除外）必须用会话 seed 派生的随机源。
2. **全量重算**：每次操作后所有指标从头算一遍（48×48 = 2304 格，全量计算目标 <10ms，不需要增量优化）。
3. **AI 只叙述不计算**：引擎产出的每一个数都是确定公式结果，AI 角色拿到的只有"指标 + 变化 + 地图摘要"，不允许 AI 返回数值写回引擎。
4. **可读性优先**：每个指标都必须能用一句人话解释（"地铁把平均通勤压到了 21 分钟"），公式选择服务于可解释性。

## 2. 世界生成（地块生成流程）

输入：seed。输出：符合 [01 §2](01-domain.md) 的 48×48 地形 + 省道。

步骤（顺序固定，保证可复现）：

| 步骤 | 规则 | 参数 |
|---|---|---|
| 1 基底 | 全 flat | — |
| 2 河道 | 从北边界随机一点入、南边界随机一点出，随机游走（每步 60% 直行/各 20% 左右）成 2–3 格宽河道带 | 河道占比 3–5% |
| 3 河岸 | 河道两侧各 1 格标记 bank | — |
| 4 丘陵 | 1–3 团簇，每团 8×8 区域内的圆/椭圆（半径随机），叠加简单噪声确定边缘 | 丘陵占比 8–12% |
| 5 林地 | 2–4 片，优先落在河岸与丘陵边缘（贴水贴山好看），生成后不可建设 | 林地占比 5–8% |
| 6 省道 | 西北角入、东南角出，45° 斜穿（每 6–8 格允许一次小偏移），宽 1 格 | 固定 1 条 |
| 7 校验 | 可建设率 ≥70%，否则回到步骤 2 重生成（最多 20 次，兜底放宽比例） | — |
| 8 简报 | 把约束（限高/绿线/可建设率）交给叙述层生成 briefing 文案 | 限高 60–100m 随机 |

冲突优先级：river > bank > inherited_road > hill > forest > flat。高优先级地形覆盖低优先级地形；省道不得覆盖河流，若路线与河流相交则沿最近可行格偏移，并保持连通。

## 3. 操作校验流程

放置请求进入后依次检查（任何一步失败立即返回 [02 §1](02-data-contract.md) 对应错误码）：

1. 会话存在且阶段 ∈ {build, polish}。
2. 区块类型合法（属于 14 种之一）、anchor 坐标在界内。
3. 覆盖格列表 = 由 anchor + 区块占地形状展开。
4. 每覆盖格地形符合 [01 §3](01-domain.md)：普通区块只允许 flat/hill；绿地还允许 bank；桥仅允许跨连续 river 并覆盖两端 bank；所有覆盖格均不得已有玩家区块。
5. 造价 × 丘陵加成 ≤ funds。
6. 全部通过 → 扣款、落块、触发全量重算。

拆除：返还 30% 造价（向上取整到元）。polish 期与 build 期规则一致，均不限次数。

## 4. 指标计算体系

以下均为**每次操作后即时重算**的规则。符号约定：Σ = 对所有已放置区块求和；d(区块A, 区块B) = 锚点格之间的曼哈顿距离（格数）。

### 4.1 funds（财政资金）

- 初始：5,000,000（配置项）。
- 放置：−造价（丘陵覆盖格 ×1.5）。
- 拆除：+⌈造价 × 0.3⌉。
- 每年末结算：+tax_income − upkeep。可为负；负值本身不判死，进入推演才判破产。

### 4.2 population（人口）

每座住宅区块有“容量”“目标入住”与“实际入住”三个内部量：

- 容量：res_low 300 / res_mid 900 / res_high 2400（配置项）。
- 吸引力 = 1 + 0.10×(500m 内公园数) + 0.08×(800m 内学校数) + 0.08×(800m 内医院数) − 0.15×(300m 内有重工业) − 0.05×(丘陵上)。
- 城市目标人口 = min(Σ(住宅容量 × min(1, 吸引力)), Σ住宅容量 × 0.95)；开局没有住宅时为 0。目标人口按各住宅的加权容量比例分配，余数按 tile id 字典序分配。
- 实际人口只在年度结算时向目标人口移动；每年最大变动量为当前住宅总容量的 8%（向上取整），因此零人口城市也能逐年迁入。年度间放置/拆除只更新目标人口，不直接改变实际人口；拆除住宅导致容量低于实际人口时，超出部分立即视为强制迁出并截到剩余总容量。
- 实际人口按各住宅目标入住比例分配到住宅区块；目标入住总和为 0 时改按住宅容量比例分配。人数取整，余数按 tile id 字典序分配。`population` = 各区块实际入住之和。

含义：配套好的房子住得满；纯堆住宅没人来。

### 4.3 jobs（岗位）

- com_shop 80 / com_cbd 1200 / ind_light 900 / ind_heavy 2600。
- jobs = Σ岗位。岗位在放置瞬间即满（简化：岗位供给即需求）。

### 4.4 job_res_ratio（职住比）

= jobs ÷ population；population 为 0 时固定为 0。=1 完美平衡；>1.5 岗位大量外溢（通勤压力↑）；<0.5 睡城（地价↓）。

### 4.5 land_price_index（地价指数）

逐住宅区块算地价再全城加权（按容量加权）：

- 基准 100。
- +8×(400m 内 com_cbd 数) + 3×(400m 内 com_shop 数)。
- +6×(600m 内 trans_metro 数)。
- +5×(300m 内 green_plaza 数) + 1×(300m 内 green_park 数)。
- −10×(500m 内 ind_heavy 数) − 4×(500m 内 ind_light 数)。
- +10 若该格在 bank（河景）。
- −8 若在 hill。
- 全城指数 = Σ(每座住宅地价×其入住) ÷ Σ入住，保留 1 位小数；无入住时固定为 100。

### 4.6 green_ratio（建设绿地占比）

= 玩家放置的 green_park / green_plaza 覆盖格数 ÷ 所有玩家区块覆盖格数；没有放置区块时为 0。不可建设的 forest 不计入分子或分母。这是玩法平衡指标，不是法定用地绿地率；评分的 0.30 目标仅作游戏归一化参考。

### 4.7 avg_commute（平均通勤）与 4.8 congestion（拥堵）

分两步。住宅需求以每座住宅的实际入住人数为单位，每座住宅分配给曼哈顿距离最近的岗位区块；距离相同时按区块 `id` 字典序选取。没有任何岗位时该住宅通勤时间记 120 分钟、不可达需求计 100%，路网负载为 0。

**第一步 路网负载**。把每座住宅的通勤需求分配到最近岗位区块：

- 通勤需求 = 该住宅实际入住（按容量比例拆分给 Σ岗位）。
- 路径：在 4 邻接格网上选择绕开 river 的最短路；road_inherited、trans_road、util_bridge 和未放置区块格都可通行，其他已放置区块格也可通行（简化为城市街区可穿行）。所有等长路径按逐格坐标 `(r,c)` 字典序确定。没有合法路径时该需求不可达，单户通勤记 120 分钟；无需另加惩罚。
- 若同一 `trans_metro` 与住宅锚点、目标岗位锚点的曼哈顿距离均 ≤12 格，则该户通勤固定为 8 分钟且不进入道路负载；否则按路网计算。
- 每格道路负载 = 分配给经过该格的住宅入住需求总和。格容量为 `highway_capacity`（road_inherited）或 `road_capacity`（其余可通行格）；桥格容量同普通道路。

**第二步 BPR 函数**（美国联邦公路局标定，核查无误）：

每条路径的通行时间 = Σ路段 t0 × (1 + 0.15×(V/C)^4)
- t0 = 所有路网格基准时间 0.5 分钟/格。
- V = 该格负载，C = 该格通行能力：普通道路/桥 800 需求，省道 1500；地铁捷径不进入路网负载。
- 拥堵度 congestion = max(所有格 V/C)。

**汇总**：avg_commute = Σ(每座住宅通勤时间×入住) ÷ Σ入住；上限截断 120 分钟。无住宅时固定为 0；`congestion` 是有需求格的最大 V/C，无道路需求时为 0。

参数 α=0.15、β=4 可调（配置项），改之前必须在 PR 描述写明对平衡性的影响。

### 4.9 pollution（污染）

- 污染源：每个 ind_heavy 区块强度 0.35、半径 3 格；每个 ind_light 强度 0.15、半径 2 格。以住宅覆盖格到工业区块最近覆盖格的曼哈顿距离计算贡献，每格距离衰减 0.05；各工业贡献相加后单格上限 1。
- 全城污染 = 所有住宅覆盖格暴露的入住加权平均；无住宅时取 48×48 全部格子的污染暴露简单平均。无住宅时不做除以 4 的额外缩放。

### 4.10 happiness（幸福度，0–100）

基准 50，加总以下修正后截断 [0,100]：

| 因子 | 规则 |
|---|---|
| 绿地 | +30 × green_ratio |
| 通勤 | avg_commute <20：+15；20–40：+10；40–60：0；60–80：−8；>80：−15 |
| 职住 | 0.85–1.15：+8；1.15–1.5 或 0.6–0.85：0；其余 −8 |
| 污染 | −40 × pollution |
| 地价 | (land_price_index−100) × 0.2，封顶 ±10 |
| 服务覆盖 | +6×coverage_edu + 6×coverage_med |
| 住房拥挤 | 若 res_high 占比 >40%：−6（鸽子笼惩罚） |

### 4.11 tax_income（年税收）

= Σ住宅入住 × 1200元/人 × (land_price_index/100) + Σ岗位 × 500元/岗。量纲：人口税 + 企业税。

### 4.12 upkeep（年维护费）

= Σ 各区块维护费（见 §8 表），与是否入住无关。

### 4.13 coverage_edu / coverage_med（覆盖率）

- 对每个住宅格，若 600m 内（12 格曼哈顿半径）存在学校 → 教育达标；600m 内有医院 → 医疗达标。
- 覆盖率 = 达标住宅入住 ÷ 总入住。无住宅时为 0。

## 5. 时间推进与年度结算

- 简报结束或被跳过时开始 build 计时；build 900 秒，恰为 3 个 300 秒游戏年。第 300/600/900 秒时依次结算到第 1/2/3 年，届满自动进入 polish。
- 每年末（后端单调时钟调度）执行结算：population 按 §4.2 向目标人口移动（每年最大变动量为当前住宅总容量的 8%，向上取整）、funds 增减，并按 §7 进行确定性事件抽样。阶段边界与操作并发时，由会话锁串行化；边界时刻先结算并推进阶段，再处理新到操作。
- polish 期 120 秒，游戏年冻结，不做年度结算；允许放置和拆除，届满自动锁定。
- locked 阶段由后端先预计算完整 10 年 `projection`（目标 <2 秒），再每 3.5 秒发布一个年度 `projection_step`；SSE 只播放已计算结果，不承担推演或补算。第 10 个切片发布后进入 report。玩家手动 `finalize` 与 polish 超时自动 finalize 走同一条流程。

## 6. 终局推演（10 年快进）

从 build 结束时的第 3 年快照出发，对第 4–13 年（10 个预测年）重复以下循环（纯 sim，无 AI）：

1. population 按 §4.2 向目标人口迁移（每年最大变动量为当前住宅总容量的 8%，向上取整）。
2. 地价、通勤、污染、幸福度全量重算。
3. 若 happiness <40 连续两年 → 人口额外 −5%（逃离潮）。
4. funds 结算；破产判定（见 [01 §7](01-domain.md)）。
5. 每年产出 0–2 条 `events` 标签（规则模板：地价涨>10%、拥堵破 0.9、幸福度跨 60 等阈值），作为确定性环境/指标事件供前端显示；其文案来源固定为 `template`。
6. 记录该年 Metrics 快照进 projection。

结局和五维评分使用第 13 年（第 10 个预测年）快照；bankrupt 仍在任意预测年触发。projection 在 finalize 响应中完整返回，SSE 只负责呈现进度，不负责计算。

五维分数均为 0–100 整数，先按公式截断到 [0,100]，再四舍五入（正数 `floor(x+0.5)`）：

| 分数 | 确定性公式（使用第 13 年快照） |
|---|---|
| population | `100 × population / 20000` |
| balance | `100 − 100 × abs(job_res_ratio − 1)` |
| green | `100 × green_ratio / 0.30` |
| traffic | `0.6 × (100 − 100 × avg_commute / 120) + 0.4 × (100 − 100 × congestion / 1.5)` |
| happiness | `happiness` |

### 6.1 零值与结局边界

- population 为 0 时职住比、覆盖率、绿地占比均为 0，通勤与拥堵均为 0；地价指数为 100。
- jobs 为 0 且人口大于 0 时职住比为 0，平均通勤为 120 分钟。
- 没有住宅容量时不判定 `ghost_town`。评分仍按上述公式计算，空城 population / balance / green / happiness 有定义，不产生除零。
- `eco_paradise` 的绿地门槛是第 13 年 `green_ratio` ≥0.55、无工业区块且人口 ≥5,000。

## 7. 环境事件池（建设期随机）

每个建设年末独立以 5% 概率触发至多一条；使用 `seed + 游戏年 + 固定事件域` 派生随机流，不能受 AI 文案或请求次序影响。文案由叙述层生成、数值影响由引擎执行。事件效果仅持续当年：

| 事件 | 数值效果 |
|---|---|
| 暴雨内涝 | 当年 upkeep +15% |
| 产业风口 | 当年岗位税收 +20% |
| 网红打卡 | 地价 +5 持续 1 年 |

## 9. 指标重算性能预算

- 单次全量重算 ≤10ms（目标，非硬约束；48×48 网格 + ≤200 区块任何语言都能轻松达到）。
- finalize 同步推演 ≤1.5s。
- 每秒 tick 最多一次；操作触发的重算与年度结算共用同一代码路径（保证一致性）。
